## 1. 문제와 목표

운영자는 매일 뉴스·이슈·연예·경제·AI 소재를 찾고, 원고를 줄이고, 이미지를 만들고,
캡션과 게시 일정을 관리해야 한다. 이 반복 작업을 한 화면에서 수행하도록 돕는다.
목표는 **매일 최대 10개의 검토 가능한 콘텐츠를 꾸준히 제작하고 예약 게시**하는 것이다.
유효한 원문이 부족하면 허위 소재로 수량을 채우지 않는다.

장기 목표는 여러 플랫폼에서 소재를 수집해 무인 운영하는 파이프라인이다.
이번 제출 범위와 장기 목표는 아래 지원표에서 구분한다.

## 2. 사용자와 핵심 시나리오

1. 원고 입력: 원고를 붙여넣고 카테고리, 톤, 장수, 비율을 선택한다.
2. 링크 입력: 기사·블로그 공개 본문 또는 YouTube 설명을 가져와 내용을 확인한다.
3. 제작: 텍스트 디자인/AI 생성/웹 이미지/보유 사진/영상 캡처 중 선택한다.
4. 검토: 카드별 제목·본문, 캡션, 출처를 수정하고 사실·권리를 확인한다.
5. 배포: ZIP으로 내려받거나 인스타그램에 예약한다.
6. 반복: 매일 설정 시각에 초안을 수집·생성하고 운영자가 검토한다.

## 4. 콘텐츠 원칙

- 첫 장에 명확한 관심 포인트, 중간에 근거와 핵심, 끝에 구체적인 CTA.
- 의혹·주장과 확정 사실을 구분한다. 실제로 확인하지 않은 댓글·인용을 만들지 않는다.
- 감동·공감 문구는 원문 사실을 왜곡하지 않는 범위에서 쓴다.
- 원문 링크, 출처 이름, 이미지 출처와 이용 조건을 저장한다.
- AI 이미지는 실제 현장 사진처럼 표시하지 않는다.
- 주제만 입력한 AI 초안은 일반 설명이며 최신 뉴스 사실 확인을 대신하지 않는다.

## 5. 제품 화면

카드뉴스 만들기 / 트렌드 탐색 / 콘텐츠 보관함 / 발행 일정 / 연결 설정.
한국어 UI와 로컬 오류 메시지, 반응형 화면, 키보드 조작을 제공한다.
제작 화면에 미리보기와 결과 다운로드를 배치한다.

## 6. 성공 측정

- 필수: 키 없는 환경에서 시연 원고 → 이미지 → 편집 → ZIP 저장 성공.
- 필수: 요구한 세 가지 비율과 1~10장 경계값 검증.
- 운영 검증: 실제 계정에 단일 카드·캐러셀·예약 게시 각 1회 성공.
- 운영 추적: 일일 생성량/미달 사유, 게시 성공·실패 수, 검토 소요 시간.
- 향후 효과 측정: 저장률·공유률·댓글률을 실제 계정 통계로 비교. 현재 수치는 없음.

## 7. 의존성과 범위 제한

GitHub 인증, 각 서비스 API 키, Meta 앱 게시 권한, 공개 HTTPS 이미지 제공 환경이 필요하다.
이 조건이 없는 상태에서 실제 게시 완료로 표시하지 않는다.
이번 MVP는 단일 운영자의 로컬 PC용이며 멀티유저 인증·과금·외부 공개 서버는 범위 밖이다.
