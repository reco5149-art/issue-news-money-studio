# 영상 자동 캡처

이미지 제작 방식에서 **보유 영상에서 캡처**를 선택하고 생성한다.
영상 파일을 선택하면 브라우저가 구간별 장면을 캡처한다.
파일을 선택하지 않으면 출처 URL(또는 링크 가져오기 입력)의 공개 YouTube 영상을
가져와 서버에서 캡처한다. 각 장면은 별도 이미지 자산으로 카드에 배치된다.
기존 단일 사진 방식과 호환되며 편집창에서 장별 교체할 수 있다.

## 범위

- 요청 장수의 3배(최대 20개) 후보를 캡처하고, 정리 검사를 통과한 장면을 시간 순으로 배분
- 20분·150MB 이하 영상, 최종 최대 10개 장면
- 등간격 구간의 중앙 시점 추출. 의미 기반 영상 분석·음성 인식·자막 추출 아님
- 비슷한 장면이 반복되는 영상에서는 사진이 유사할 수 있음
- 원고는 별도로 입력하거나 가져오기. YouTube 가져오기는 제목·설명만 지원
- 링크 다운로드 실패 시 오류를 표시하고 파일 선택으로 진행
- 로그인 쿠키 사용, 접근 제한 우회, Instagram/TikTok 링크 다운로드 미지원
- 실제 게시 전 장면·문안 일치와 원본 영상 이용 조건 확인

## 실행 환경

requirements의 yt-dlp와 PATH의 FFmpeg/ffprobe가 필요하다.
브라우저 파일 캡처는 FFmpeg 없이 가능하다. 링크 캡처는 서버가 임시 영상을 받고
캡처 후 삭제한다. URL은 YouTube 호스트·영상 ID를 검사해 표준 URL로 다시 구성한다.
타임아웃과 동시 링크 처리 1건 제한을 적용한다.

## 로고·홍보 화면 정리 (2026-10-01)

YouTube 링크와 보유 파일 모두 캡처 후보를 서버의 AI 검사에 전달한다.
원본을 덮어쓰지 않고, 가장자리·하단을 제외하는 크롭 후보의 실제 픽셀을 각각 검사한다.
뉴스 로고·출처 박스·방송 자막·구독 안내가 남거나 주요 얼굴·동작이 잘렸다고 판단한
후보는 제외한다. 모든 크롭이 부적합하면 그 시점의 장면을 사용하지 않는다.
자동 장수에서는 사용 가능한 장면을 최대 10개 반환하고, 원고에 필요한 장수와 비교한다.
사진이 부족하면 원문에서 해당 장수로 재구성하며 마지막 카드와 CTA를 단순 삭제하지 않는다.
사진이 하나도 없으면 화면에서 텍스트 카드로 전환하고 안내한다.
직접 지정한 장수보다 사진이 적을 때만 장수 조정 오류를 표시한다.
실제 사물의 표식·깃발·현장 표지판은 지우지 않으며 합성으로 빈 공간을 채우지 않는다.

OpenAI API 키가 필요하며 원고 엔진이 로컬이어도 캡처 정리에는 API 비용이 발생한다.
OPENAI_FRAME_MODEL 기본값은 gpt-4.1. 후보 프레임마다 최대 3회 검사, 동시에 3개 프레임을
처리한다. 비용과 대기 시간은 후보 수·재검사 수에 따라 달라진다.
AI 판단이므로 모든 로고 제거 또는 모든 핵심 인물 보존을 보장하지 않는다.
완성 카드의 별도 자가평가(v2)에서도 방해되는 방송 그래픽·홍보 화면을 검사한다.
출처 URL과 캡처 시각은 이미지 크레딧에 보존하고 기존 출처·캡션 체계를 유지한다.
기존 저장 카드에는 소급 적용하지 않으며 새로 생성할 때 적용한다.

검증: 크롭 범위·최소 해상도, 후보 재시도, 홍보 장면 제외, 적합한 장면 부족 시 중단,
불완전 AI 응답 차단을 자동 테스트한다. 보유 파일 경로는 같은 정리 함수를 사용한다.

실제 API 검증: 기존 YouTube 영상에서 15개 후보를 검사해 5장 반환(HTTP 200).
반환 이미지 5장의 로고·방송 자막·구독 엔딩 제외를 육안 확인했다.

자동 장수 회귀 검증: count=0 유지, 적합 사진 1장/0장 처리, 원고 4장→사진 2장 재구성 검증.
2026-10-01 전체 pytest 53개 통과(기존 미커밋 KIE·네이버 변경 테스트 포함), JS 구문 검사 통과.
